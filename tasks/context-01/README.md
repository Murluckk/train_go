# Отмена через context

Реализуй:

```go
func Drain(ctx context.Context, ch <-chan int) (int, error)
```

Складывает значения из канала, пока канал не закроют. Если контекст
отменили раньше — прекращает работу и возвращает причину.

## Требования

- Канал закрыли — вернуть накопленную сумму и `nil`.
- Контекст отменили или истёк дедлайн — вернуть **сумму, накопленную к
  этому моменту**, и ошибку из `ctx.Err()`. Проверяется через
  `errors.Is(err, context.Canceled)` и
  `errors.Is(err, context.DeadlineExceeded)`.
- Уже отменённый контекст — ничего не читать, вернуть `0` и ошибку,
  даже если в канале что-то лежит.
- `Drain` не должна блокироваться после отмены.
- Никаких гонок: тесты гоняются с `-race`.

## Где обычно ошибаются

`select` из двух готовых каналов выбирает случайный. Если данные и
отмена приходят одновременно, функция может прочитать ещё одно значение
после отмены — и на это есть тест, который гоняет сценарий много раз.
Проверка `ctx.Err()` в начале итерации решает вопрос.
