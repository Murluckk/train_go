# Свой UnmarshalJSON для Duration

`time.Duration` — это `int64`, и `encoding/json` по умолчанию сериализует
его как наносекунды. В конфигах так писать невозможно. Сделай тип, который
понимает обе формы.

```go
type Duration time.Duration

func (d *Duration) UnmarshalJSON(data []byte) error
func (d Duration) MarshalJSON() ([]byte, error)
```

## Требования

- Строка разбирается через `time.ParseDuration`: `"1m30s"`, `"500ms"`, `"2h"`.
- Число трактуется как **секунды**: `30` → 30 секунд. Дробные тоже:
  `1.5` → 1.5 секунды.
- `null` оставляет значение нетронутым и не считается ошибкой — так
  ведут себя стандартные типы.
- Любой другой JSON (объект, массив, `true`) — ошибка.
- Некорректная строка — ошибка, и она должна упоминать исходное значение,
  иначе в конфиге на сто строк её не найти.
- `MarshalJSON` всегда пишет строку в формате `time.Duration.String()`:
  `"1m30s"`. Round-trip через Marshal → Unmarshal обязан сохранять значение.

## Где обычно ошибаются

`UnmarshalJSON` получает **сырой** JSON, включая кавычки. Разбирать его
руками через `strings.Trim` — прямой путь к багу на экранированных
символах: используй `json.Unmarshal` во временную переменную.

Метод объявляется на указателе (иначе присваивание некуда девать), а
`MarshalJSON` — на значении, чтобы работал и для `Duration`, и для
`*Duration`.
