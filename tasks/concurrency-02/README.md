# select с таймаутом

Реализуй:

```go
var ErrTimeout = errors.New("истекло время ожидания")
var ErrClosed = errors.New("канал закрыт")

func WaitFor(ch <-chan int, timeout time.Duration) (int, error)
```

Ждёт значение из канала не дольше `timeout`.

## Требования

- Пришло значение — вернуть его и `nil`.
- Истёк таймаут — вернуть `0` и ошибку, для которой
  `errors.Is(err, ErrTimeout)` истинно.
- Канал закрыли, не прислав значение — вернуть `0` и `ErrClosed`.
  Закрытый канал отдаёт нулевое значение немедленно и бесконечно, так что
  без проверки второго результата получится не таймаут, а мгновенный ноль.
- `nil`-канал ведёт себя как «никогда»: должен сработать таймаут.
- `timeout <= 0` — не ждать вообще: если значение уже готово, забрать его,
  иначе сразу `ErrTimeout`.
- Функция не должна оставлять за собой висящие горутины.

## Где обычно ошибаются

`time.After` в цикле создаёт новый таймер на каждой итерации. Здесь цикла
нет, но привычка проверять «а сколько раз я создаю таймер» — полезная.
